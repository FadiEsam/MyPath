## 1. Purpose

This document defines the functions that MyPath must provide.

Each requirement describes an expected system capability without specifying its database structure, API implementation, or interface design.

## 2. Requirement Priority

- **Initial:** Required for the initial personal-use version.
- **Later:** Planned for a later development phase.
- **Future:** A possible expansion that requires further analysis.

## 3. Skills Management

### FR-001: Create Skills

The system shall allow the user to create a skill, such as PHP, JavaScript, SQL, UI/UX Design, or Software Testing.

Priority: Initial.

### FR-002: Update Skills

The system shall allow the user to update a skill's information.

Priority: Initial.

### FR-003: Record Skill Level

The system shall allow the user to record their current knowledge or proficiency level for a skill.

Priority: Initial.

### FR-004: Record Learning Evidence

The system should allow the user to associate relevant courses, tasks, or projects with a skill as evidence of learning or practice.

Priority: Initial.

### FR-005: Track Skill Development

The system shall support reviewing a skill's development using recorded activities and available time data.

Priority: Initial.

## 4. Learning Activities and Courses

### FR-006: Create Learning Activities

The system shall allow the user to record learning activities, including courses, practice tasks, and other learning work.

Priority: Initial.

### FR-007: Record Course Information

The system shall support recording a course title, learning resource link, expected duration when known, and completion status.

Priority: Initial.

### FR-008: Record Learning Outcomes

The system should allow the user to record what was learned and any resulting skill development, certificate, or practice work.

Priority: Initial.

### FR-009: Complete Learning Activities

The system shall allow the user to mark an activity as completed and record its completion date.

Priority: Initial.

## 5. Projects and Work Phases

### FR-010: Create Projects

The system shall allow the user to create and manage projects.

Priority: Initial.

### FR-011: Organize Project Phases

The system shall allow the user to organize a project into work phases, such as UI/UX, Database, Backend, Frontend, and Testing.

Priority: Initial.

### FR-012: Associate Work with Skills

The system should allow project phases and tasks to be associated with relevant skills.

Priority: Initial.

### FR-013: Track Project Status

The system shall allow the user to identify a project's current status.

Priority: Initial.

### FR-014: Record Project Outcomes

The system should allow the user to record completed work and the final project outcome.

Priority: Initial.

## 6. Time Tracking

### FR-015: Start a Timer

The system shall allow the user to start tracking time for a supported activity.

Priority: Initial.

### FR-016: Pause and Resume a Timer

The system shall allow the user to pause and resume an active timing session.

Priority: Initial.

### FR-017: Finish a Timing Session

The system shall allow the user to finish a timing session and retain its recorded duration.

Priority: Initial.

### FR-018: Record Time Manually

The system should allow the user to record time spent on work that was not tracked by the timer, including external learning or offline work.

Priority: Initial.

### FR-019: Associate Time with Work

The system shall associate recorded time with the relevant activity and, when applicable, its project phase and skill.

Priority: Initial.

### FR-020: Review Recorded Time

The system shall allow the user to review recorded time by relevant categories, including activity, project, and skill.

Priority: Initial.

## 7. Progress and Performance Analysis

### FR-021: Review Activity History

The system shall allow the user to review completed and ongoing activities.

Priority: Initial.

### FR-022: Summarize Time Spent

The system shall summarize recorded time over selected periods and relevant work categories.

Priority: Initial.

### FR-023: Review Completed Work

The system shall summarize completed tasks, learning activities, and projects using recorded data.

Priority: Initial.

### FR-024: Compare Periods

The system should allow the user to compare performance across weekly and monthly periods.

Priority: Initial.

### FR-025: Display Evidence-Based Progress

The system shall calculate summaries from available records and shall not present unsupported progress values when required data is missing.

Priority: Initial.

## 8. Services and Portfolio

### FR-026: Manage Services

The system should allow the user to define services they may offer, including a description, required skills, and other relevant details.

Priority: Later.

### FR-027: Associate Projects with Services

The system should allow the user to associate suitable projects with relevant services.

Priority: Later.

### FR-028: Present Portfolio Information

The system should support organizing selected projects and skills as portfolio evidence.

Priority: Later.

## 9. Freelance and Financial Tracking

### FR-029: Record Clients and Work

The system should allow the user to record freelance clients and their related work.

Priority: Later.

### FR-030: Track Invoices and Payments

The system should support recording invoices, payment status, and received payments.

Priority: Later.

### FR-031: Record Business Expenses

The system should support recording expenses, including hosting and other service costs.

Priority: Later.

### FR-032: Summarize Financial Results

The system should calculate financial summaries using recorded income, expenses, and applicable payment information.

Priority: Later.

### FR-033: Review Financial Performance

The system should support monthly financial comparisons and service-level performance analysis.

Priority: Later.

## 10. Future Expansion

### FR-034: Support Future User Accounts

The system may support multiple users, authentication, permissions, and separate user data in a future version.

Priority: Future.

### FR-035: Support Different Views

The system may provide separate views for personal career tracking, public portfolio presentation, recruiters, or clients.

Priority: Future.

### FR-036: Support Additional Technologies

The system should be designed so that its implementation can evolve as the project grows, without requiring unnecessary redesign of its core concepts.

Priority: Future.
